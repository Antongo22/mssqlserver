# SQL Server в Docker

## GUI и сервер одной командой

```bash
docker compose up -d --build
```

Откройте **http://localhost:3001**. Compose запускает SQL Server и локальный
MSSQL Studio (GUI + Node.js API). Панель стартует после готовности SQL Server.
Оба сервиса перезапускаются автоматически, пока не остановлены вручную.
При первом запуске в новой копии проекта используйте `./scripts/start.sh` —
он также создаст `.env`, если файла ещё нет.

Кнопка темы в правом верхнем углу переключает светлое и тёмное оформление,
включая SQL-редактор, таблицы и формы. Выбор сохраняется в браузере. Пока тема
не выбрана вручную, панель следует настройке операционной системы.

### Дополнительные инструменты

**Подключения.** Слева над списком баз находятся выбор сервера и кнопка
«Подключения». Укажите имя, адрес, порт, SQL-логин, пароль и окружение; кнопка
проверки соединения не сохраняет профиль. Для сервера на компьютере из Docker
используйте `host.docker.internal`. Поддерживается SQL-аутентификация, TLS включён;
доверие самоподписанному сертификату выбирается явно. Смена сервера блокируется во
время SQL-запроса и открытой формы. Каждый HTTP-запрос привязан к своему подключению
заголовком `X-Studio-Connection`, в том числе при параллельной работе вкладок.
При ошибке подключения панель не переключается незаметно на локальный сервер.

Настройки подключений и расписаний сохраняются в томе `mssqlserver_studio`:
`/config/settings.json`, права `0600`, каталог `0700`. Пароли хранятся на бэкенде
в этом файле и не возвращаются API списка подключений. Это не зашифрованное
хранилище: доступ к Docker-томам даёт доступ к настройкам. При обычном открытии
страницы выбирается встроенный локальный сервер.

**Автодополнение.** SQL-редактор загружает схемы, таблицы, представления и все их
столбцы, поддерживает алиасы (`SELECT p. FROM dbo.Products AS p`). После `JOIN `
предлагаются готовые соединения по существующим FK с условием ON, в том числе по
составным ключам. Метаданные обновляются при смене базы и после SQL-запроса.
Подсказки предназначены для обычных FROM/JOIN; сложные CTE и динамический SQL
могут потребовать ручного ввода.

**Графический план.** Кнопки «Оценочный план» и «Запрос + план» показывают дерево
операторов с раскрываемыми ветками. Красный цвет — собственная оценочная стоимость
от 30% стоимости дерева, жёлтый — от 10%. Стоимость является оценкой оптимизатора,
а не измеренным временем. Фактические строки суммируются по потокам, когда SQL Server
их возвращает. Табличный вид и скачивание исходного `.sqlplan` сохранены.

**Сравнение схем.** Выберите сервер и базу источника и приёмника, затем «Сравнить».
Можно раскрыть каждое отличие, скачать миграцию или открыть её в редакторе,
автоматически выбрав подключение и базу приёмника. Скрипт не запускается сам.
Поддерживаются обычные таблицы, столбцы, PK/UNIQUE, обычные индексы (включая INCLUDE
и фильтр), FK, CHECK и определения views/procedures/functions/triggers.
Объекты только в приёмнике сохраняются. Изменения IDENTITY, вычисляемых полей,
DEFAULT, существующих индексов/ключей и специальные свойства требуют ручной
миграции: для них выводятся различия и предупреждения. Порядок SQL-модулей и
зависимости при ALTER COLUMN следует проверить; это не автоматическая миграция
любой схемы. Пользовательские типы, partitioning, temporal, memory-optimized,
права, репликация и данные не переносятся этим инструментом.

**Предпросмотр структуры.** В формах изменения таблицы первое нажатие подготавливает
SQL и список зависимостей из системного каталога, второе применяет изменение.
При изменении полей формы предпросмотр подготавливается заново. Список зависимостей
относится ко всей таблице и включает SQL-объекты, входящие FK, индексы и ограничения;
он не обнаруживает динамический SQL и внешние приложения. Произвольный SQL в
редакторе выполняется обычным способом.

**Импорт.** Откройте таблицу → «CSV / Excel», выберите файл до 5 МБ, разделитель
CSV либо лист XLSX. Первая строка служит заголовками; сопоставьте их целевым
столбцам или пропустите лишние. На экране показаны первые 20 строк. Кнопка
«Проверить значения» проверяет SQL-типы, длину строк, обязательные поля и NULL;
до успешной проверки импорт недоступен. Типы определяются структурой целевой
таблицы. Ограничения: до 500 строк, 100 столбцов, JSON запроса до 2 МБ.
Формат `.xls` не поддерживается. Формулы не вычисляются, используется сохранённый
результат; для точных больших чисел в Excel используйте текстовые ячейки.
FK, UNIQUE, CHECK и триггеры проверяются SQL Server при вставке; ошибка откатывает
все строки импорта. Парсер Excel работает в отдельном worker с ограничением
памяти и времени. Для строк используется маркер NULL `\N`, пустая строка сохраняется.

**Расписание копий.** Выберите базу → «Расписание копий». Интервал задаётся в
минутах (1–10080), хранение — в днях (1–3650). Первый запуск происходит через
заданный интервал; можно сразу нажать «Запустить». Планировщик работает в admin
каждые 10 секунд и после перезапуска выполняет просроченное расписание один раз.
Копии создаются с COPY_ONLY/COMPRESSION/CHECKSUM, затем проходят VERIFYONLY.
Дополнительная проверка восстанавливает копию в уникальную временную базу,
выполняет `DBCC CHECKDB WITH PHYSICAL_ONLY` и удаляет только эту временную базу.
История содержит последние 100 запусков. Пауза и удаление расписания не удаляют
бекапы. Очистка после успешного запуска затрагивает только просроченные файлы
данного расписания и сохраняет последнюю успешную копию. При остановленном Docker
задания не выполняются. Проверка восстановлением требует места для ещё одной БД.

Для внешнего SQL Server бекапы требуют общего каталога, доступного и серверу,
и контейнеру admin: укажите серверный путь в профиле, затем смонтируйте тот же
каталог в `/backups/<ID подключения>` admin. ID возвращает API `/api/connections`.
Без настроенного общего каталога используйте SQL-команды бекапа на внешнем сервере;
встроенный Docker SQL Server настроен для всех операций автоматически.

**Избранные запросы.** Над редактором: «Сохранить запрос» и «Избранное».
Укажите название и параметры, например `@CustomerId` типа INT. При открытии
заполните форму, затем нажмите «Выполнить». Значения передаются отдельными
типизированными параметрами и не подставляются в SQL строковой заменой.
Доступны строки, INT/BIGINT, DECIMAL(38,10), BIT, DATE/DATETIME2 и GUID, а также NULL.
До 100 запросов и 30 параметров на запрос. Определения хранятся в localStorage;
введённые значения параметров не сохраняются. Редактирование SQL, смена вкладки
запроса или базы сбрасывает значения — откройте запрос из избранного повторно.

### Даталогическая модель базы

Выберите базу и откройте **Модель БД**. Диаграмма автоматически строится по
метаданным SQL Server: все пользовательские таблицы, включая таблицы без PK и без
связей, столбцы и SQL-типы, первичные и уникальные ключи, существующие внешние ключи.
Разные схемы, составные ключи, несколько FK между таблицами, циклы и ссылки на
саму таблицу поддерживаются. Раскладка выполняется локально в Web Worker с помощью
[ELK](https://github.com/kieler/elkjs); внешние сервисы не используются.

- **Обновить** перечитывает структуру и перестраивает модель. Она также обновляется
  при открытии вкладки и переключении базы.
- Колесо мыши / кнопки `−` и `＋` меняют масштаб, перетаскивание перемещает весь холст,
  **Вместить** показывает модель целиком. Доступен полноэкранный просмотр.
- Поиск находит таблицы по схеме, имени или столбцам; выберите результат в списке
  или нажмите Enter, чтобы перейти к первой найденной таблице.
- Нажатие таблицы показывает её столбцы, ключи и связи. Нажатие линии показывает
  все пары столбцов FK, действия ON DELETE / ON UPDATE и состояние ограничения.
  Составной FK представлен одной линией с подсветкой всех участвующих столбцов.
- `PK` — первичный ключ; `UK` — участие в уникальном ключе/индексе без фильтра;
  `FK` — внешний ключ; `?` — допускается NULL. Состав ключа целиком виден в панели
  сведений: значок на отдельном столбце не означает, что он уникален сам по себе.
- Линии направлены от родительского PK/UNIQUE к дочернему FK. Надпись
  `1 : N` / `0..1 : N` показывает допустимую кратность: `N` означает `0…N`.
  Если дочерний FK ограничен подходящим уникальным ключом, справа будет `0..1`.
  Пунктир означает отключённый или не проверенный на существующих данных FK;
  для него кратность отражает объявленную структуру, а не гарантию целостности данных.
- **SVG** сохраняет всю модель в текущей светлой/тёмной теме, включая таблицы за
  пределами видимой области. Файл открывается отдельно от панели.
- С клавиатуры: Tab выбирает таблицу/связь, Enter открывает сведения; на холсте
  стрелки перемещают модель, `+`/`−` меняют масштаб, `0` вмещает её, Escape снимает выделение.

Это автоматически созданная модель **только для просмотра**: ручное создание,
перемещение отдельных таблиц и редактирование связей не предусмотрены. Изменять
структуру можно в существующих разделах панели, затем обновлять диаграмму.
Совпадение имён столбцов не считается связью — отображаются только объявленные FK.
Просмотр использует `GET /api/databases/:database/diagram`, читает системный каталог
и не читает строки пользовательских таблиц. Сборка включает локальные JS/CSS и worker;
обычный `docker compose up -d --build` запускает всё необходимое.

### Внешние ключи при создании таблицы

В форме **Создать таблицу → Внешние ключи → ＋ Внешний ключ** выберите PK
существующей таблицы. Список загружается запросом из каталога выбранной базы:
есть поиск по схеме, таблице, имени ключа и столбцам, а также кнопка обновления.

При выборе PK форма автоматически добавляет столбец для каждого поля ключа,
назначает имя вида `TestTable_Id`, нужный тип и отключает AUTO. При совпадении имён
добавляется суффикс `_2`, `_3` и т. д. Собственный `Id` новой таблицы сохраняется.
Имя можно изменить вручную; повторный выбор того же PK в этой связи использует
ранее созданные столбцы. При смене PK прежние столбцы сохраняются для ваших правок.
**＋ Новый столбец** добавляет ещё один вариант; **Применить тип PK** меняет тип
уже выбранного столбца. При необходимости можно вручную выбрать другой столбец FK.
Поддерживаются несколько FK и ссылки на составные PK с явным сопоставлением всех
столбцов в правильном порядке. Можно задать имя ограничения, действия ON DELETE /
ON UPDATE и посмотреть SQL связи. Для SET NULL столбцы должны допускать NULL.
Если выбран локальный столбец AUTO (IDENTITY), при удалении и обновлении
доступен только NO ACTION. Обычно `Id` оставляют собственным
автоинкрементным ключом, а для FK добавляют отдельный столбец, например `CustomerId`,
без AUTO. Форма объясняет ограничение и блокирует несовместимые действия.

Таблица и все FK создаются одной командой CREATE TABLE: при несовместимом типе,
устаревшем PK или другой ошибке таблица не остаётся частично созданной.
Ссылки на специальные пользовательские типы создавайте через SQL-редактор.

### Запрос с сортировкой

1. Выберите базу и откройте **SQL-редактор → Шаблон → SELECT: фильтры и сортировка**.
2. Выберите таблицу, выводимые столбцы и при необходимости фильтр.
3. Укажите «Сначала по» и порядок ASC/DESC; можно добавить ещё два поля сортировки.
4. Нажмите **Открыть в редакторе**, проверьте SQL, затем **Выполнить**.

Например, конструктор может подготовить:

```sql
SELECT TOP (100) [Id], [Name], [CreatedAt]
FROM [dbo].[Products]
ORDER BY [CreatedAt] DESC, [Id] ASC;
```

### Резервные копии на компьютере

- **Резервные копии → Копия текущей базы** создаёт полный COPY_ONLY-бекап с COMPRESSION и CHECKSUM.
- **Скачать** сохраняет `.bak` через обычное скачивание браузера на ваш компьютер.
- **Восстановить с компьютера** позволяет выбрать локальный `.bak`, задать имя новой базы и восстановить её после загрузки и проверки.
- Также можно отдельно **Загрузить .bak**, **Проверить** и **Восстановить** из списка файлов.
- Для файлов больше 512 МБ скопируйте их в `/var/opt/mssql/backups` контейнера MSSQL, например через `docker compose cp /путь/к/backup.bak mssql:/var/opt/mssql/backups/backup.bak`, затем проверьте права чтения/записи для пользователя `mssql`.

Копии находятся в отдельном томе `mssqlserver_backups`. Обычная остановка и
`./scripts/reset.sh` сохраняют их. `docker compose down -v` удаляет **и базы, и копии**.
Скачанный на компьютер файл не зависит от Docker. VERIFYONLY проверяет копию,
но полноценную проверку восстановления можно выполнить, восстановив её в новую базу.
Восстановление через форму не перезаписывает существующие базы; для сложного
RESTORE (цепочки журналов, FILESTREAM, перезапись) используйте SQL-редактор.

### Поведение и границы

Панель — локальный инструмент с правами `sa`, без отдельного входа. Пароль сервера
не отправляется в браузер. API проверяет локальный Host, Origin и специальный заголовок.
Подтверждения в формах не ограничивают произвольный SQL с правами администратора.

- Редактирование/удаление строки требует PK (включая составной) и проверяет хеш исходных значений. При конфликте обновите таблицу. Без PK доступны чтение и вставка, изменение — через SQL.
- BIGINT и DECIMAL в формах данных передаются строками, без потери точности JavaScript. Произвольные результаты SQL используют представление драйвера.
- Каждый запуск SQL открывает отдельное подключение. `GO` сохраняет сессию внутри запуска; между нажатиями «Выполнить» временные таблицы и открытые транзакции не сохраняются.
- До 100 блоков `GO`, включая повторы `GO n`. Тайм-аут выбирается от 1 до 600 секунд. Отмена не отменяет уже зафиксированные операции.
- Флажок «В транзакции» оборачивает скрипт в транзакцию и откатывает её при ошибке. Не используйте в этом режиме команды, запрещённые внутри транзакции, или собственные COMMIT/ROLLBACK.
- Показ результатов: до 1000 строк на набор, 5000 строк, 20 наборов и 4 МБ суммарно. Эти ограничения не ограничивают число изменяемых строк.
- CSV-экспорт содержит только показанные данные; потенциальные формулы экранируются апострофом. Импорт CSV/XLSX: до 500 записей, файл до 5 МБ; IDENTITY и вычисляемые поля нельзя сопоставлять для вставки.
- Вкладки и последние 50 успешных запросов сохраняются в localStorage этого браузера; история может содержать значения из SQL. Её можно очистить в панели.
- Скрипт DDL предназначен для основной структуры обычных таблиц. Специальные свойства (partitioning, temporal, compression, columnstore, INCLUDE и т. п.) проверяйте вручную.
- Это расширенная рабочая консоль, а не полная копия SSMS: нет редактора диаграмм БД, отладчика T-SQL, мастеров репликации/Always On, SSIS/SSAS/SSRS и полного конструктора многошаговых заданий Agent.

Для просмотра журналов панели: `docker compose logs --tail 100 admin`.

## Запуск и проверка

```bash
./scripts/start.sh
./scripts/check.sh
```

Compose собирает локальный образ из `Dockerfile` в текущей директории.
SQL-файлы также копируются в контейнер в `/usr/src/sql/`.
После изменения Dockerfile или SQL-файлов пересоберите образ: `docker compose up -d --build --wait`.

При первом запуске скрипт создаёт `.env` со случайным паролем `sa`, скачивает образ
и ждёт готовности сервера. Проверка показывает версию, создаёт `LearningDB` и таблицу
`dbo.Students`, проверяет добавление, чтение, изменение и удаление записи.
Тестовые изменения откатываются; существующие записи сохраняются.

## Свои запросы

```bash
./scripts/sql.sh -Q "SELECT @@VERSION"
./scripts/sql.sh -d LearningDB -Q "SELECT * FROM dbo.Students"
./scripts/sql.sh < sql/02-demo.sql
```

SQL-файлы можно открыть и выполнить в любом клиенте SQL Server.

## Подключение из клиента

- Сервер: `localhost,1433` (в клиентах с отдельным полем порта: `localhost`, порт `1433`).
- Аутентификация: SQL Server, пользователь `sa`.
- Пароль: значение `MSSQL_SA_PASSWORD` из локального `.env`.
- База: `LearningDB` после запуска проверки, либо `master`.
- Включить доверие сертификату сервера (`Trust server certificate`).

Порт доступен только на этом компьютере. `.env` исключён из Git.
Чтобы выбрать другой порт, измените `MSSQL_PORT` в `.env` и повторите запуск.
Изменение пароля в `.env` не меняет пароль в уже созданной базе данных.

## Управление

```bash
docker compose ps
docker compose logs --tail 100 mssql
./scripts/stop.sh
./scripts/start.sh
```

Данные находятся в именованном Docker volume и сохраняются после остановки.
Команда `docker compose down -v` удаляет оба тома — базы и резервные копии.
Для сброса баз с сохранением копий используйте `./scripts/reset.sh`.

Если сервер не запускается на Apple Silicon, проверьте поддержку эмуляции amd64
в настройках Docker Desktop и выделение достаточной памяти (не менее 4 ГБ).

## Полный сброс

```bash
./scripts/reset.sh
```

Без дополнительного подтверждения удаляет контейнер и том данных этого проекта,
включая все пользовательские базы, таблицы, записи и настройки SQL Server.
Затем запускает чистый сервер и ждёт его готовности. Удаление данных необратимо.
Другие Docker-проекты не затрагиваются; файлы проекта, `.env` и отдельный том
резервных копий `mssqlserver_backups` сохраняются.
Пароль `sa` при повторной инициализации берётся из `.env`.

После сброса остаются только системные базы. Чтобы заново создать учебную
`LearningDB` и проверить запросы, выполните `./scripts/check.sh`.
